# Caller history

The call list now shows the caller number, total recorded calls for that number within this clinic, phone search (4–15 digits), and a number link that opens the caller's history. Each call retains its independent ID, transcript, actions and outcome. The detail view also links back to caller history. The count covers all recorded calls, while date/engine/status filters can narrow the displayed results. Numbers may be shared, withheld, reassigned or spoofed: they group carrier identities, not verified people or patients.

New calls save validated E.164 caller metadata from the existing authenticated gateway. No new environment variables are required. Numbers are kept on the tenant-scoped call summary, outside the technical event allowlist and trace payloads. Phone searches use a POST body, and summary/detail responses use `Cache-Control: no-store`. Existing clinic authentication, membership checks and database RLS remain unchanged. Phone retention follows retained call summaries; this feature does not implement a separate phone deletion policy.

`20260927000400_voice_caller_history.sql` was applied directly to the configured Supabase database on 27 September 2026. Column/index/RLS/staff-policy verification passed, and the actual backend call-list SQL executed successfully. One existing call number was recovered through an exact organization/provider-call match in `voice_call_sessions`. Calls without that trustworthy match remain null; patient records and transcripts are never used to infer the caller number. Recovery provenance appears in the detail view.

The migration is additive and idempotent. It does not recreate or edit a missing Supabase migration ledger. The helper `scripts/apply_voice_caller_history.py` applies only this migration using configured local credentials and prints verification booleans/counts, never credentials or numbers. The read-only checks are in `supabase/verification/20260927000400_voice_caller_history_checks.sql`.
